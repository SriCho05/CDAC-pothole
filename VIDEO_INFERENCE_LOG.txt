4. INITIAL PYTORCH PROBLEMS
----------------------------
The system Python initially had no pip and no torch:

  /usr/bin/python3: No module named pip
  ModuleNotFoundError: No module named 'torch'

A project virtual environment was created:

  inference/.venv

The generic installed PyTorch was initially:

  torch 2.14.0+cu130

This was incompatible with the Jetson CUDA driver. CUDA initialization reported
that the driver was too old (detected driver version 12060 for that wheel).

The generic torch and torchvision packages were removed. NVIDIA's JetPack wheel
was installed instead:

  torch 2.5.0a0+872d972e41.nv24.08

The first NVIDIA URL used was missing a build suffix and returned HTTP 404. The
valid JetPack v61 wheel included:

  17622132

The final wheel URL used was:

  https://developer.download.nvidia.com/compute/redist/jp/v61/pytorch/torch-2.5.0a0+872d972e41.nv24.08.17622132-cp310-cp310-linux_aarch64.whl

5. cuSPARSELt PROBLEM AND FIX
-----------------------------
After installing the NVIDIA PyTorch wheel, importing torch failed with:

  ImportError: libcusparseLt.so.0: cannot open shared object file

The PyTorch installation instructions require cuSPARSELt for PyTorch releases
from 24.06 onward. The installer script initially failed with CUDA_VERSION=12.6
because that script only supports CUDA 12.1 through 12.4 for that package.

The script was rerun with:

  export CUDA_VERSION=12.4

The archive downloaded and extracted successfully. The first copy attempt used
an incorrect temporary directory. The actual extracted directory was:

  /tmp/libcusparse_lt-linux-sbsa-0.5.2.1-archive

The headers and libraries were copied with sudo into /usr/local/cuda, followed by
sudo ldconfig. LD_LIBRARY_PATH was set to include:

  /usr/local/cuda/lib64
  /usr/local/cuda/targets/aarch64-linux/lib

After this fix, PyTorch imported successfully and CUDA became available.

6. NUMPY COMPATIBILITY WARNING
-------------------------------
The NVIDIA PyTorch wheel was compiled against NumPy 1.x, while NumPy 2.2.6 was
initially installed. Importing torch produced a NumPy ABI warning and failed to
initialize NumPy support.

NumPy was downgraded to a 1.x release. The environment later reported:

  NumPy 1.26.4

This removed the NumPy ABI incompatibility.

7. TORCHVISION INSTALLATION
---------------------------
Ultralytics requires torchvision. It was initially missing:

  PackageNotFoundError: No package metadata was found for torchvision

A generic PyPI torchvision package was avoided because it could be incompatible
with NVIDIA's Jetson PyTorch build.

The torchvision v0.20.0 source repository was cloned and built:

  https://github.com/pytorch/vision.git
  branch: v0.20.0

The first build caused the Jetson Orin Nano to reboot, most likely because the
parallel C++ compilation exhausted available memory.

The board had approximately:

  RAM: 7.4 GiB
  Swap: 3.7 GiB

The build was repeated with:

  MAX_JOBS=1
  CMAKE_BUILD_PARALLEL_LEVEL=1
  CFLAGS=-O0
  CXXFLAGS=-O0

The second build completed successfully:

  torchvision 0.20.0
  wheel: linux_aarch64, cp310

A verification attempt from /tmp/vision incorrectly imported the source tree and
reported torchvision::nms errors. This was caused by the current directory
shadowing the installed package. Running from inference/ avoids that issue.

14-20 FPS measurements at the default 640px inference size. It is near real-time
but not fully real-time for this 25 FPS video because processing takes about 2.4

especially for small potholes, so detections should be compared against the 640px
run before selecting this setting for deployment.

13. POSSIBLE PERFORMANCE IMPROVEMENTS
-------------------------------------
Test a smaller inference size:

  --image-size 416

or:

  --image-size 320

This should improve throughput but may reduce detection accuracy, especially for
small potholes.

Reduce latest-frame writes during testing:

  --latest-frame-interval 5

The runner could also be optimized by writing latest frames atomically, moving
SQLite/event image writes off the critical inference loop, and reducing status JSON
write frequency. These changes should be benchmarked against detection accuracy
and event reliability before deployment.
