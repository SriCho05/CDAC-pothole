SECTION 1: PHYSICAL MOUNTING SPECIFICATIONS
--------------------------------------------------------------------------------

1.1 RGB CAMERA (Primary Detection)
    Recommended: Sony IMX219 / IMX477 (CSI-2, 8MP/12MP) or USB3 UVC
    Mounting:
      - Position: Front-center of vehicle, behind windshield
      - Height: 1.2m - 1.5m from ground
      - Pitch: 10° - 15° downward (road plane fills lower 60-70% of FOV)
      - Yaw: 0° (straight forward) or 2-3° toe-in for convergence at 3-5m
    Resolution: 1920×1080 @ 30fps minimum (1280×720 acceptable)
    Lens: Wide-angle (120°-160° HFOV) for road coverage
    Why: Primary detection sensor — YOLO runs on this feed

1.2 THERMAL CAMERA (LWIR, Fusion & Night)
    Recommended: FLIR Boson 640 / Seek Thermal CompactPro / Teledyne FLIR Lepton 3.5
    Mounting:
      - Position: Co-located with RGB, same optical axis
      - Baseline (horizontal separation): ≤5 cm (minimizes parallax)
      - Vertical offset: ≤2 cm (optical centers aligned)
      - Same pitch/yaw as RGB
    Resolution: 640×512 @ 9-30fps (Boson) or 160×120 @ 9fps (Lepton)
    Lens: Match RGB HFOV (±5%) — e.g., 9-13mm for 640×512
    Why: Night detection, waterlogging (thermal contrast), thermal bbox_xywh

1.3 GNSS RECEIVER (Position + Timestamp)
    Recommended: u-blox ZED-F9P (RTK, 10Hz) or u-blox M8N (10Hz)
    Mounting:
      - Antenna: Roof-mounted, clear sky view (magnetic base or pole)
      - Cable: USB/UART to Jetson (/dev/ttyACM0 or /dev/ttyUSB0)
      - Baud: 115200 (NMEA GGA/RMC + UBX for RTK)
    Output: Lat/Lon/Alt, speed, heading, UTC timestamp, fix quality
    Why: frame_id geo-location, UTC sync for sensor fusion

1.4 IMU (9-Axis: Accel + Gyro + Mag)
    Recommended: MPU-9250 / ICM-20948 / Xsens MTi-3 (I2C/SPI)
    Mounting:
      - Position: Rigidly fixed to camera rig (same vibration profile)
      - Orientation: X=forward, Y=left, Z=up (vehicle frame)
      - Cable: I2C (0x68/0x69) or SPI to Jetson header
    Output: 100-200Hz accel/gyro/mag, vibration RMS, orientation
    Why: Vibration gating, frame stabilization, road roughness estimation

1.5 LUX SENSOR (Ambient Light / Auto-exposure)
    Recommended: TSL2591 / BH1750 / VEML7700 (I2C)
    Mounting:
      - Position: Co-located with cameras, facing forward
      - Unobstructed by hood/wiper
    Output: 0-88000 lux (TSL2591), 1-65535 lux (BH1750)
    Why: Day/night classification, exposure control, payload environment.lux

4.3 CALIBRATION WORKFLOW (inference/calib/)

    Step 1: Intrinsics (per sensor)
      - Checkerboard 8×6, 30mm squares
      - 20+ frames per sensor, varying distance/angle
      - cv2.calibrateCamera() → K_rgb, K_thermal, K_realsense, dist_*

    Step 2: Extrinsics (RGB ↔ Thermal)
      - Same checkerboard visible to both simultaneously
      - cv2.stereoCalibrate() → R, T, E, F
      - Verify reprojection error <0.5px

    Step 3: RealSense RGB-Depth Alignment
      - Factory-calibrated; librealsense `align` utility maps depth→RGB pixels
      - Validate: project known checkerboard depth against measured distance
      - Expected error: <2% at 4m

    Step 4: LiDAR-Camera Extrinsics (RGB ↔ LiDAR)
      - Calibration target: planar checkerboard + LiDAR-reflective target
      - Simultaneous capture: LiDAR point cloud + camera image
      - Solve PnP: LiDAR points on checkerboard plane → camera image corners
      - Or: use planar target + PnP on LiDAR plane fit + camera detection
      - Verify: project LiDAR points → camera image; target <1px error at 5m

    Step 5: Road-Plane Homography (RGB ↔ Thermal)
      - Vehicle height (1.3m) + pitch (12°) known
      - H = K_thermal * [R|T] * inv(K_rgb) (road plane Z=0)
      - Project RGB bbox → thermal bbox_xywh

    Step 6: IMU-Camera Extrinsics
      - IMU frame → Camera frame transform
      - Kalibr or manual measurement (rigid mount)

    Step 7: RealSense Built-in IMU
      - 6-DoF IMU data available via librealsense
      - Can supplement/fuse with external IMU for vibration gating

4.4 INFERENCE PIPELINE INTEGRATION (local_runner.py modifications)

    Current: capture → preprocess → inference → postprocess → storage
    Proposed:
      1. FramePacket arrives (all sensors synced)
      2. IMU vibration gate: if RMS < threshold → skip, log event
      3. Lux gate: if < 100 lux → thermal-only mode
      4. 160px scene-change detector on RGB
      5. If ROI: crop 224px → YOLO inference
      6. SORT tracking across frames
      7. If tracked: bbox update via tracker (skip YOLO)
      8. Project bbox to thermal via homography H
      9. Depth fusion:
           a. RealSense: sample depth map inside pothole ROI → median depth
           b. LiDAR: project points via R,t → camera pixels → filter by ROI
              → fit local road plane → depth = perpendicular distance to plane
      10. estimated_depth_cm, area_sqcm from depth source (prefer LiDAR >6m)
      11. Build C-DAC payload (all fields populated)
      12. Async: storage + API queue


SECTION 5: CALIBRATION TARGETS & VALIDATION
--------------------------------------------------------------------------------

5.1 ACCURACY TARGETS
    - RGB↔Thermal bbox IoU: >0.85 (after homography)
    - RGB↔RealSense depth alignment: <1px (factory-aligned, validate <1px)
    - LiDAR→Camera projection error: <2px at 10m, <1px at 5m
    - GNSS timestamp sync: <1ms jitter
    - IMU vibration detection: 95% recall for pothole impact
    - Depth error (RealSense): <2% at 4m (per Intel spec)
    - Depth error (LiDAR): ±2cm (per Livox spec) on flat road
    - Pothole depth estimation error: <10% for 0.5-5m range

5.2 VALIDATION PROCEDURE
    1. Static: Checkerboard at known distances → verify reprojection
    2. RealSense depth validation: measure known distances at 1m, 3m, 5m
    3. LiDAR projection: project known targets → camera image, measure pixel error
    4. Dynamic: Drive known pothole course → compare detected vs truth
    5. Night: Thermal detection recall vs RGB day baseline
    6. Vibration: IMU spike correlation with detected anomalies
    7. Cross-validation: RealSense depth vs LiDAR depth in 0-6m overlap region
    7. Water-filled: controlled test pothole with known depths + water

5.3 FAILURE MODES
    - Thermal dropout → fallback to RGB only (payload thermal_xywh=null)
    - RealSense dropout → fallback to LiDAR depth (log warning)
    - LiDAR dropout → fallback to RealSense (0-6m) or RGB only
    - GNSS loss → last known position + dead reckoning (IMU)
    - IMU failure → disable vibration gating, run full inference
    - Sync loss >2 frames → alert, re-initialize sync
    - Water/rain on lens → thermal/RealSense dropout; hydrophobic coating recommended

APPENDIX A: DEPTH SENSING RESEARCH SUMMARY (2026-09-25)
--------------------------------------------------------------------------------

A.1 TECHNOLOGY LANDSCAPE: STEREO, TOF, STRUCTURED LIGHT, LIDAR

| Technology                    | Principle                           | Outdoor/Sunlight Robustness          | Key Limitation                             |
|-------------------------------|-------------------------------------|--------------------------------------|--------------------------------------------|
| Passive stereo (ZED)          | Triangulation from two RGB          | Bright sunlight (needs ambient)      | Fails on low-texture (wet asphalt)         |
| Active IR stereo (RealSense)  | Triangulation + IR pattern          | Good; degrades facing sun            | IR pattern washed out in direct sun        |
| Structured light (Kinect)     | Known IR pattern projected          | Poor — indoor tech                   | Unusable outdoors in daylight              |
| Time-of-Flight (Azure Kinect) | Phase/pulse delay of IR/laser       | Weak-moderate; ambient IR raises noise| Low resolution; degrades in sun           |
| Scanning LiDAR, 905nm         | Scanned laser ToF, sparse 3D pts    | Strong — light-independent           | Sparse at range; no submerged bottom       |
| Bathymetric LiDAR, 532nm      | Green laser for water penetration   | Strong, purpose-built                | Expensive, survey-grade                    |
| Monocular learned depth       | Single RGB, network-inferred depth  | As robust as RGB camera              | Relative, scale-ambiguous only             |

Key findings:
- Active IR stereo (RealSense) sits closer to LiDAR in outdoor robustness than
  structured light or ToF, because depth comes from triangulation between two
  IR sensors' own images, not from a single active signal.
- No non-bathymetric technology (stereo, ToF, structured light, 905nm LiDAR)
  should be assumed capable of measuring a submerged pothole bottom. Bathymetric
  532nm green-wavelength LiDAR is the only technology designed for this.

A.4 PHYSICAL MOUNTING GEOMETRY (LiDAR + Camera)

- Mount camera and LiDAR close together, both pointing forward and slightly
  downward (10°-15° pitch) to observe road ahead
- Baseline ≤10cm between LiDAR and camera (minimize parallax for projection)
- They do NOT need identical FOV or same physical point — overlap is what
  matters; parallax is modeled by extrinsic calibration
- Forward-and-downward orientation preferred (detect pothole before reaching)
- RealSense unit: co-located with RGB, factory-aligned (no extrinsics needed)

A.5 COORDINATE TRANSFORMATION (LiDAR → Camera)

LiDAR point: P_L = [X_L, Y_L, Z_L]^T in LiDAR frame
Camera point: P_C = R · P_L + t
where R = 3×3 rotation matrix, t = translation vector

Camera projection (pinhole model):
u = fx · Xc / Zc + cx
v = fy · Yc / Zc + cy

RealSense: no R,t needed — depth map already pixel-aligned to its RGB stream.
librealsense `align` utility maps depth → camera pixel grid directly.

A.6 SUPERIMPOSITION MEANING

"Superimposition" = software calculates where each 3D LiDAR point projects in
the camera's 2D image:
LiDAR point cloud → LiDAR-to-camera R,t → camera projection → pixel (u,v)
→ draw/associate point with camera frame.

Result: colorized camera view with LiDAR points overlaid, or programmatically
intersect projected points with YOLO pothole bbox/mask.

A.7 YOLO + DEPTH FUSION ARCHITECTURE

Semantic (YOLO): 'Where is pothole and what class?'
Geometric (LiDAR/RealSense): 'What is 3D geometry in that region?'

Pipeline:
1. RGB frame → YOLOv8 → pothole bbox / segmentation mask
2. LiDAR: point cloud → R,t transform → project to camera pixels
   RealSense: depth map already in camera pixel grid
3. Filter points/pixels inside pothole ROI/mask
4. Fit local road plane from surrounding points
5. Pothole depth = perpendicular distance from plane to pothole points

A.8 DEPTH ESTIMATION METHODOLOGY

Do NOT use raw sensor distance to pothole directly. Vehicle/sensor/road
orientations vary, and road is not a perfect horizontal plane.

Method:
1. Surrounding road points → fit local reference plane:
   a·x + b·y + c·z + d = 0
2. Perpendicular distance from point to plane:
   distance = |a·x + b·y + c·z + d| / √(a² + b² + c²)
3. Use physically meaningful vertical/depth component per vehicle frame

Applies to both LiDAR points and RealSense 3D points (deprojected from depth).

A.9 MINIMAL PROJECTION CODE (LiDAR → Camera)

```python
P_lidar = np.array([X, Y, Z])
P_camera = R @ P_lidar + t
Xc, Yc, Zc = P_camera
if Zc > 0:
    u = fx * Xc / Zc + cx
    v = fy * Yc / Zc + cy
    cv2.circle(frame, (int(u), int(v)), 3, color, -1)
```

RealSense equivalent: `depth_frame.get_distance(u, v)` gives depth in meters;
`rs.rs2_deproject_pixel_to_point(intrin, [u, v], depth)` gives 3D point.

A.10 CALIBRATION REQUIREMENTS

- Camera intrinsics: fx, fy, cx, cy, distortion coefficients
- LiDAR-camera extrinsics: R (3×3), t (3×1) — NOT needed for RealSense RGB-depth
- Temporal sync: camera and LiDAR observations ≈ same instant (GNSS PPS + timestamps)
- Mechanical stability: bracket must prevent vibration/movement post-calibration
- Validation: project LiDAR points onto known targets at several distances;
  for RealSense, validate reported depth vs manual reference at 1m, 3m, 5m

A.10 WATER-FILLED POTHOLES — EXPERIMENTAL STUDY DESIGN

Conventional 905nm LiDAR + RealSense D455f: both return water surface, not
submerged bottom (IR/NIR absorbed/scattered by water). Bathymetric 532nm
green-wavelength LiDAR is the specialized category for this.

Controlled test protocol:
1. Construct depression with known dimensions
2. Progressively add water: dry → shallow clear → deep clear → turbid/muddy
3. Record: true depth, water depth, sensor returns
4. Conditions: incidence angles, ranges, times of day
5. Output: water-surface return vs submerged-bottom return for each sensor

If neither LiDAR nor RealSense resolves bottom → document limitation.
If bathymetric 532nm LiDAR available → comparative test.

A.11 RISKS & LIMITATIONS

- LiDAR point density may be insufficient for small potholes at speed
- RealSense: 6m recommended range; degrades in direct sun, water, low texture
- D455f recommended over D455 for outdoor (IR-pass filter)
- No IP rating on D455/D455f → D456/D457 for IP65 if exposed
- Water/rain/fog/dust/reflective surfaces affect both sensors
- Calibration errors + timestamp offsets → projection misalignment
- Bounding-box fusion includes normal road around pothole → segmentation preferred
- Neither LiDAR nor RealSense should be marketed as bathymetric
