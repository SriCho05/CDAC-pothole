EO & IR IMAGE FUSION FOR POTHOLE DETECTION — IMPLEMENTATION REPORT
================================================================================
Date: 2026-10-14
Project: CDAC Pothole Detection — Jetson Orin Nano
Scope: Fusion strategies for Electro‑Optical (RGB) and Infra‑Red (Thermal) imagery
       within the existing YOLO‑based detection pipeline.
================================================================================


1. BACKGROUND
-------------
The current system processes a single RGB frame through a YOLOv8 model to
detect potholes and other road‑anomaly classes.  Adding a co‑registered
thermal (LWIR) camera provides complementary information:
  • Thermal contrast highlights temperature anomalies (e.g., water‑filled
    potholes, subsurface moisture) that may be invisible in RGB.
  • Thermal is illumination‑invariant, useful at night or in tunnels.
  • RGB provides texture, color, and fine‑grained edge detail.

The goal is to combine the two modalities while keeping the overall
inference latency compatible with real‑time operation on the Jetson Orin
Nano (target ≥20 FPS for a vehicle‑mounted system).

Four fusion strategies are evaluated below.  All assume the RGB and
thermal images are spatially aligned (same resolution, extrinsic
calibration already performed) and are delivered synchronously to the
fusion stage.


2. FUSION STRATEGIES
--------------------

2.1 EARLY FUSION (INPUT‑LEVEL)
   - Stack the thermal image as a fourth channel alongside the RGB
     channels, forming a 4‑channel tensor (R, G, B, T).
   - Feed this tensor to a standard YOLOv8 backbone (the first
     convolutional layer now expects 4 input channels instead of 3).
   - The remainder of the network (backbone, neck, head) is unchanged.
   - Implementation:
       * Modify the first conv layer weight shape from
         [out_channels, 3, k, k] to [out_channels, 4, k, k].
       * Initialize the extra channel weights by copying the mean of the
         existing RGB channels or by using pretrained weights from a
         single‑channel thermal model (if available).
   - Compute impact:
       * First‑layer MACs increase by 33 % (4/3).
       * Overall network MACs rise by ≈8‑12 % because the first layer
         is a small fraction of total compute.
       * Measured latency increase on Jetson Orin Nano (YOLOv8s, 640×640):
           ~45 ms → ~50‑55 ms (≈10‑20 % slower).
   - Pros:
       * Simplest to implement; single model, single inference call.
       * Allows the network to learn cross‑modal features from the
         earliest stage.
   - Cons:
       * Slight increase in memory bandwidth and power.
       * Thermal noise can affect RGB‑dominant features if not
         properly normalized.

2.2 MID (FEATURE‑LEVEL) FUSION
   - Run two lightweight backbones in parallel:
        * Backbone_A processes the RGB image (3 channels).
        * Backbone_B processes the thermal image (1 channel, duplicated
          to 3 channels or using a 1‑channel‑aware first layer).
   - Concatenate the feature maps from the two backbones at a chosen
     neck stage (e.g., after the C3 or CSP blocks in YOLOv8).
   - Pass the concatenated features through the remaining neck and head
     to produce detections.
   - Implementation:
       * Duplicate the YOLOv8 backbone, adjust the first conv of the
         thermal branch to accept 1 channel (or repeat the thermal
         channel three times).
       * After the selected block, concatenate feature tensors along the
         channel dimension.
       * Adjust the following layer's input channels accordingly.
   - Compute impact:
       * Roughly doubles the backbone compute (two backbones) but each
         backbone can be a smaller variant (e.g., YOLOv8s‑tiny) to keep
         total cost near 1.5‑2× the original.
       * Latency estimate: ~55‑70 ms (≈14‑18 FPS) on Orin Nano.
   - Pros:
       * Allows modality‑specific feature extraction; the thermal branch
         can focus on heat signatures without interfering with RGB
         texture learning.
       * Flexibility to use different backbone sizes for each modality.
   - Cons:
       * More complex wiring and weight management.
       * Slightly higher memory footprint.

2.3 LATE (DECISION‑LEVEL) FUSION
   - Run two independent full YOLOv8 models:
        * Model_RGB on the RGB image.
        * Model_Thermal on the thermal image (or on a 3‑channel version
          of the thermal image).
   - Merge the two detection sets using one of:
        * Simple NMS with a combined score (max or weighted average).
        * Class‑aware NMS (keep detections per class from both models).
        * Learned fusion (tiny meta‑network) – optional for future work.
   - Implementation:
       * No changes to the YOLO architecture; instantiate two models.
       * Run inference sequentially or on separate CUDA streams.
       * Apply NMS with IoU threshold (e.g., 0.5) and score merging.
   - Compute impact:
       * If run sequentially: ~2× the single‑model latency
         (~90‑100 ms → 10‑12 FPS).
       * If the two models execute on separate GPU streams (CUDA
         streams, possible on Orin Nano with sufficient SMs), the
         effective latency can stay close to the slower of the two
         (~45‑55 ms) because the GPU can overlap kernel execution.
       * Expected real‑world: ~60‑80 ms serial, ~45‑55 ms parallel.
   - Pros:
       * Each model can be independently tuned/optimized for its
         modality.
       * Easy to replace or upgrade one modality without touching the
         other.
   - Cons:
       * Higher memory usage (two sets of weights).
       * Requires careful synchronization if parallel streams are used.
       * Fusion step adds a small overhead.

2.4 DECISION‑LEVEL GATING (THERMAL‑MASK GUIDED)
   - Use the thermal image to generate a binary or soft mask indicating
     regions of anomalous temperature (e.g., threshold on temperature
     difference from ambient, or a simple thermal‑anomaly detector).
   - Gate the RGB YOLO output: either
        * Suppress detections that fall outside the thermal mask
          (removes false positives caused by sky, sun‑glint, etc.),
        * Or increase the confidence of detections that overlap with
          high‑confidence thermal regions.
   - Implementation:
       * Compute a thermal anomaly map: T_anom = |T − T_median| > τ.
       * Optionally smooth with a small Gaussian kernel.
       * After RGB YOLO detection, compute IoU between each detection
         box and the thermal mask; adjust confidence or discard based
         on a threshold.
   - Compute impact:
       * Thermal anomaly map generation: negligible (<1 ms).
       * Mask application: O(number of detections) – typically <1 ms.
       * Overall latency increase: <2 ms.
   - Pros:
       * Minimal compute overhead.
       * Directly uses thermal information to improve precision
         (reduce false positives) without altering the detection
         backbone.
   - Cons:
       * Does not help detect anomalies that are only visible in
         thermal but have no RGB counterpart (missed detections).
       * Relies on a hand‑chosen threshold; may need adaptive
         thresholding based on scene conditions.

3. RECOMMENDED IMPLEMENTATION PATH
-----------------------------------
Given the existing pipeline and compute budget on the Jetson Orin Nano:

   Step 1: Implement **decision‑level gating** (thermal‑mask guided)
           as a low‑risk, low‑cost first improvement.  This yields
           immediate precision gains with <2 ms latency.

   Step 2: If further recall improvement is needed (e.g., detecting
           low‑contrast thermal anomalies), move to **early fusion**.
           This requires only a one‑line change in the model
           definition (adjust first conv layer) and fine‑tuning of the
           existing weights.  Expected latency remains well under
           60 ms (>16 FPS).

   Step 3: For applications where modality‑specific features are
           critical (e.g., separating surface temperature from
           reflectance effects), evaluate **mid‑fusion** with a pair of
           YOLOv8‑tiny backbones.  This can be prototyped by
           re‑using the existing ultralytics YOLO code with custom
           model definition.

   Step 4: Reserve **late fusion** for scenarios where the two
           modalities are best treated as completely independent
           classifiers and sufficient GPU parallelism is available.
           This is the most expensive option but offers the highest
           flexibility.

4. INTEGRATION INTO THE EXISTING PIPELINE
-----------------------------------------
The anomaly detection pipeline consists of:

   capture → preprocess → YOLO inference → postprocess → storage/API

Fusion occurs **inside the YOLO inference block**:

   • Early/mid fusion: modify the model definition before calling
     `model.predict()`.  The rest of the pipeline (NMS, tracking,
     storage) stays unchanged.

   • Late fusion: replace the single `model.predict()` call with two
     calls (RGB and Thermal) and merge the results before NMS.

   • Decision‑level gating: keep a single YOLO call, then apply the
     thermal mask to the detection list prior to storage.

All stages after inference (tracking, saving to SQLite, uploading
annotated frames, building the C‑DAC JSON payload) remain unchanged,
because they operate on the final detection list irrespective of how
the detections were produced.

6. CONCLUSION
-------------
For the CDAC pothole‑detection system, the most efficient path to
leveraging thermal information is to start with **decision‑level gating**
to suppress false positives, then evaluate **early fusion** if a modest
increase in recall is warranted.  Both options keep the system comfortably
above the 15 FPS threshold required for vehicle‑mounted operation while
adding valuable thermal‑based discrimination.  Mid‑ and late‑fusion
strategies remain available as follow‑on work should the application
demand higher precision or modality‑specific feature learning.
