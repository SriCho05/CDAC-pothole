4. WHAT CHANGED IN THE CODE (all committed in 3a7fd92)
--------------------------------------------------------------------------------
4.1 inference/app.py
    - InferenceLoop refactored into three threads: producer (video decode +
      CPU preprocess -> pre_queue, depth 3), inference (TensorRT + BoxTracker
      + draw + JPEG encode), db worker (batched SQLite writes, 25 rows or
      0.5 s).
    - TRTInference: pinned (page-locked) host buffers; output shape read from
      the engine instead of hardcoded (1,5,8400) so 1-class and 10-class
      engines share one path; best-class-per-anchor selection; class-aware
      NMS; close() frees device buffers and pops the CUDA context.
    - /video-feed rewritten to the publisher/subscriber model: registers as a
      subscriber, yields the latest published JPEG when the sequence
      advances, unregisters on disconnect, and closes the stream once the
      pipeline is idle so a finished video does not hang the browser.
    - InferenceLoop.start() is now restartable (tears down the previous run,
      frees the GPU, rewinds the capture); the status becomes "finished" on
      EOF.
    - @app.on_event("shutdown") -> shutdown_inference(), alongside the
      atexit hook.
    - CLASS_COLORS: per-class BGR overlay colours; class_id/label carried
      through the tracker, the overlay and the DB rows.

4.2 inference/annotate/train_pipeline.py
    - prepare_yolo_dataset(): YOLO-standard images/labels tree with a
      class-stratified 80/10/10 split (seed 42). Trains on the original
      frames/, never export/annotated/ (those renders have boxes drawn on
      them, which teaches the model to find boxes).
    - build_trt_engine(): INT8 now goes through build_int8_engine.py (the
      TensorRT Python API with IInt8EntropyCalibrator2). trtexec has no
      --calib option, so the previous INT8 path could not have worked.
    - New flags: --val-ratio, --test-ratio, --no-amp, --workers, --plots.

4.3 inference/build_int8_engine.py
    - Reads the input shape off the parsed network and builds a matching
      min=opt=max profile (a static ONNX input otherwise fails the build
      with "static dimensions don't match kMAX dimensions in profile").
    - --cache option: each model needs its own calibration cache.

4.4 inference/annotate/env_setup.py (new)
    - ensure_cuda_libs(): re-execs with LD_LIBRARY_PATH set so
      pip-installed libcudss.so.0 resolves; sets
      PYTORCH_NVML_BASED_CUDA_CHECK=0 for the Tegra iGPU.
    - cuda_lib_env(): env dict for spawning subprocesses.

4.5 inference/run_int8_video_trt.py
    - postprocess() generalised for multi-class output + class-aware NMS, so
      both engines are measured with identical code.

4.6 inference/validate_engine_parity.py (new)
    - Compares the engine, its PyTorch source and the ground-truth labels on
      the same frames: greedy IoU>=0.5 agreement, mAP50/precision/recall for
      both models, and a confidence threshold sweep.
    - IMPORTANT: PyTorch and pycuda each own a primary CUDA context and
      cannot be alternated inside one loop (cuDNN STREAM_MISMATCH /
      "invalid resource handle"). The script runs one full PyTorch pass and
      then one full TensorRT pass.

  GPU: Orin (nvgpu), driver 540.4.0, nvpmodel MAXN_SUPER

  a) DEVICE MEMORY CEILING. The Orin Nano shares 7.6 GB of RAM between the
     desktop and the GPU. A 1536 MB CUDA allocation succeeds, 2048 MB fails,
     and the failure surfaces as "NVML_SUCCESS == r INTERNAL ASSERT FAILED"
     because the Tegra driver cannot report a CUDA OOM through NVML. This is
     why training must run at batch 1. Inference is unaffected.
  b) The desktop (VS Code, Chromium, gnome-shell) holds ~4.7 GB. Freeing
     memory before a training run helps.
  c) Any script that imports torch must go through env_setup.ensure_cuda_libs()
     and run with PYTORCH_NVML_BASED_CUDA_CHECK=0.
  d) Demo videos: "demo.mp4" (10 MB) and "demo 60fps.mp4" (147 MB) in
     /home/edgeai/Documents/Srikaanth CDAC/
  e) The app binds one GPU engine; the standalone scripts load their own.
     Do not run both at once.
  f) demo.mp4 plays once; the feed ends with status "finished" and is
     restarted via /api/feed/start.
  g) Never commit secrets; inference/.env.example is the template only.

6. HOW TO RUN / VERIFY
--------------------------------------------------------------------------------
  # Unified app with the retrained engine
  cd CDAC-pothole && .venv/bin/python inference/app.py \
      --engine inference/retrained/best_retrained_int8.engine

  # Reproduce the whole chain (train -> ONNX -> INT8)
  .venv/bin/python inference/annotate/train_pipeline.py \
      --annotations inference/annotations --model inference/best.pt \
      --epochs 50 --batch 1 --workers 0 --run-name poc_retrain_50 \
      --tensorrt --int8 --calib-set inference/calib_images

  # Re-validate the engine against the labels
  .venv/bin/python inference/validate_engine_parity.py \
      --model inference/retrained/best_retrained.pt \
      --engine inference/retrained/best_retrained_int8.engine --sweep

  # Benchmark an engine on demo.mp4
  .venv/bin/python inference/run_int8_video_trt.py \
      --engine inference/retrained/best_retrained_int8.engine \
      --video "/home/edgeai/Documents/Srikaanth CDAC/demo.mp4" --confidence 0.15
