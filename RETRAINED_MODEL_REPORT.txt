1. WHAT WAS DONE
================================================================================
1.1 Retraining
    The earlier run (runs/detect/poc_full-3) had trained for only 2 epochs and
    reached mAP50 0.0098 - not converged and not a fair baseline. It was
    rerun from inference/best.pt for 50 epochs on the corrected YOLO dataset
    tree produced by prepare_yolo_dataset():

        python inference/annotate/train_pipeline.py \
            --annotations inference/annotations --model inference/best.pt \
            --epochs 50 --batch 1 --workers 0 --run-name poc_retrain_50

    Training set: 49 train / 14 val / 7 test images, 520 labelled boxes,
    imgsz 640, batch 1, AMP on, seed 42.

    Batch size had to be 1: the Orin Nano shares 7.6 GB of RAM between the
    desktop and the GPU. A 1536 MB CUDA allocation succeeds and a 2048 MB
    allocation fails, and the failure surfaces as the misleading
    "NVML_SUCCESS == r INTERNAL ASSERT FAILED" error because the Tegra
    driver's NVML path cannot report a CUDA OOM. batch 2 and batch 4 both
    OOM at that point. This is a device memory ceiling, not a model problem.

1.2 Dataset split fix
    prepare_yolo_dataset() now builds a YOLO-standard tree
    (annotations/yolo_dataset/{images,labels}/{train,val,test}) because
    Ultralytics resolves a label file by rewriting the "/images/" path
    component to "/labels/". The flat export/ layout is not loadable.
    Splits are stratified by the set of classes present in each frame.
    Training always uses the ORIGINAL frames/ images, never
    export/annotated/ - those renders have the detection boxes drawn on
    them, and training on them teaches the model to find boxes.

1.3 ONNX export
    opset 12, onnxslim applied. Output shape (1, 14, 8400) = 4 bbox
    channels + 10 class channels, 8400 anchors.

1.4 INT8 TensorRT build
    Built with the TensorRT Python API and IInt8EntropyCalibrator2 over 500
    images from inference/calib_images (31 batches), 2 GB workspace.

    The exported ONNX has a STATIC input shape (1,3,640,640), so
    build_int8_engine.py now reads the shape off the parsed network and
    builds a matching min=opt=max profile. The previous fixed profile
    (max batch 16) was rejected by TensorRT with "Input tensor images has
    static dimensions that don't match kMAX dimensions in profile index 0".

    Each model needs its own calibration cache - reusing the original
    model's cache would apply the wrong activation ranges. build_int8_engine.py
    gained a --cache option for this.

1.5 Multi-class support in the runtime
    The deployed app previously hardcoded the single-class output shape
    (1, 5, 8400) and treated every detection as "pothole". The runtime now:
      - reads the output shape from the engine (1x5x8400 for the original
        1-class engine, 1x14x8400 for the retrained 10-class engine),
      - selects the best class per anchor instead of a fixed column,
      - runs class-aware NMS (each class is offset into its own coordinate
        region so two classes never suppress each other),
      - carries class_id and label through the BoxTracker, the live overlay
        (per-class colour), and the SQLite event rows,
      - the benchmark script run_int8_video_trt.py was generalised the same
        way so both engines are measured with identical code.

  The inference loop was refactored into three threads:
      producer  : video decode + CPU preprocess -> pre_queue (depth 3)

      db worker : batches pothole events into SQLite (25 rows or 0.5 s)

      213 frames delivered in 5 s        = 42.6 FPS over the wire

      JPEG encoding                     = only while a subscriber is connected
      subscriber count                  = 1 during, 0 after disconnect

  Before this refactor the whole pipeline ran at ~13 FPS end to end.

================================================================================
5. IMPORTANT CAVEATS
================================================================================
5.1 The dataset is 70 frames from a single video (demo.mp4), 520 boxes, all of
    class 0 (pothole). The validation and test splits come from the same
    source video as the training split, so the mAP50 figures above are
    optimistic as a generalisation estimate. They are valid as a
    before/after comparison between the two engines on identical data, which
    is what this report claims - not as a production accuracy figure.

5.2 The 9 non-pothole classes have NO training signal. The label files
    contain 520 boxes, every one of them class 0. The 10-class head is
    structurally present and the runtime plumbing is verified end to end
    (class-aware NMS, per-class overlay colours, per-class event labels), but
    the model has learned nothing about cracks, rutting, debris,
    waterlogging, missing lane markings, edge breaks, manholes or road
    barriers. Argmax statistics over 200 frames show 60k anchors assigned to
    class 1 and 32k to class 2 purely from the untrained head's priors; at
    the operating threshold all surviving detections are class 0.
    Labelling the 9 remaining classes is the single highest-value dataset
    task remaining.

5.3 The INT8 engine keeps 0.644 of the 0.840 mAP50 of its FP32 source
    (-23 % relative). This is the usual cost of post-training quantization
    and is the reason the operating threshold is set to 0.10 rather than 0.25.
    Quantization-aware training would close most of that gap.

5.4 The device memory ceiling (1536 MB per CUDA allocation) constrains
    training to batch 1. It does not affect inference, which needs well
    under 100 MB.
