ROAD ANOMALY DETECTION & COCO/YOLO DATASET PIPELINE - IMPLEMENTATION REPORT
===========================================================================

Project:  CDAC edge road-anomaly survey (Jetson Orin Nano deployment)
Phase:    1 - Pipeline validation, local anomaly detection, and dataset build
Date:     2026-10-09 (initial: 2026-10-06)
Scope:    Local pre-annotation, reannotation, and train/deploy tooling (inference/annotate/)

---------------------------------------------------------------- 1. OBJECTIVE

Stand up the dataset build path for the multimodal road-anomaly survey: run the
existing YOLO pothole model locally over captured frames, then review and correct
the results in a local annotation app, producing (a) YOLO training labels and
(b) the C-DAC JSON detection payload format for client staging review. All
processing stays on-host - no phone upload, no cloud inference, consistent with
the Jetson-only deployment constraint.

---------------------------------------------------------------- 2. ARCHITECTURE

images / video
      |
      v
preannotate.py  -- local YOLO inference -->  annotations/
      |                                        |- manifest.json      (frame registry: path, dims, timestamp_us)
      |                                        |- predictions.json   (rich detections: class, conf, severity, depth, area)
      |                                        |- labels/*.txt       (5-column YOLO labels)
      |                                        |- frames/            (video-only extracted frames)
      v
annotation_app.py + annotate.html  -- local FastAPI review UI (127.0.0.1:8765)
      |   canvas box editor: draw / move / resize / delete
      |   per-frame class, severity, confidence, depth, area
      |   per-frame telemetry (GPS, speed, heading, IMU) + environment (lux, surface, weather)
      v
GET /api/export  -->  annotations/export/
                        |- labels/<frame_id>.txt        (YOLO training labels)
                        |- payloads/<frame_id>.json     (one C-DAC payload per frame)
                        |- payloads.jsonl               (combined payload stream)
                        |- annotated/<frame_id>.jpg     (frames with boxes drawn on them)
                        |- coco/annotations.json        (COCO detection dataset)
                        |- manifest.json                (frame registry)

Source images are referenced in place (image-directory mode) or extracted to
annotations/frames/ (video mode). Annotated JPGs are generated on demand by the
/api/frames/{id}/annotated endpoint and in bulk by /api/export; the editable
source of truth is always the label data, never the rendered JPG.

---------------------------------------------------------------- 3. CLASS REGISTRY (10 CLASSES)

  ID  Class                     ID  Class
   0  pothole                   5  waterlogging
   1  crack_transverse          6  missing_lane_marking
   2  crack_longitudinal        7  edge_break
   3  rutting                   8  manhole
   4  debris                    9  road_barrier

Matches the 8-12 class target in the dataset specification (potholes,
transverse/longitudinal cracks, rutting, debris/obstructions,
waterlogging/puddles, missing lane markings, edge breaks, manholes, road
barriers).

Severity is area-derived: level_1 < 400 cm^2 < level_2 < 1500 cm^2 < level_3,
with manual override in the UI.

---------------------------------------------------------------- 4. DATA FORMATS

YOLO label (5-column, normalized, ultralytics-compatible):

    <class_id> <center_x> <center_y> <width> <height>
    0 0.429688 0.927083 0.109375 0.131944

C-DAC detection payload (per frame):

    {
      "frame_id": "TARAMANI_ROAD_02_09_2026",
      "timestamp_unix_us": 1787042200123456,
      "telemetry": {
        "latitude": 12.985612, "longitude": 80.241289, "altitude_m": 14.2,
        "speed_kmh": 50, "heading_deg": 184.2, "imu_vibration_g": 0.18
      },
      "environment": { "lux": 42000, "surface": "asphalt_dry", "weather": "clear" },
      "detections": [{
        "class": "pothole", "severity": "level_2", "confidence": 0.91,
        "bbox_rgb_xywh": [480, 620, 140, 95],
        "bbox_thermal_xywh": null,
        "estimated_depth_cm": 6.5, "estimated_area_sqcm": 820.0
      }]
    }

bbox_thermal_xywh is reserved for the LWIR feed and is null in the RGB-only
PoC stage. bbox_rgb_xywh is top-left [x, y, width, height] in source pixels.

COCO export (export/coco/annotations.json) is generated from the same
FrameRecord store: standard images/annotations/categories structure,
top-left pixel bbox, 1-based category ids (class_id + 1), area = w*h,
iscrowd = 0, plus score and severity preserved as extra keys. Pair it
with the source images directory (file_name is the image basename) for
pycocotools or COCO-format fine-tuning.

Authority model: predictions.json is authoritative for rich attributes
(severity, confidence, depth, area) because the 5-column YOLO label cannot
store them; the label file is the fallback geometry source and the training
artifact. All writes are atomic (temp file + rename).

---------------------------------------------------------------- 5. PRE-ANNOTATION BEHAVIOR (preannotate.py)

- Input: image directory (optionally --pattern '*.jpg,*.png') or video file
  (--every N frame stride; frames extracted to annotations/frames/).
- Frame identity: filename stem (deduplicated) or <video>_<NNNNNN> for video.
- Timestamp: file mtime in microseconds; video frames add frame_index / fps.
- Inference: local best.pt via Ultralytics YOLO, configurable --conf and
  --image-size, device auto-selects cuda:0 when available.
- Model classes map to the registry by name; unmapped classes are counted and
  skipped rather than silently mislabeled.
- Progress logged every 100 frames with fps; class histogram printed at the end.

---------------------------------------------------------------- 6. REVIEW UI (annotate.html)

- Dark, single-file canvas editor (no build step, no external dependencies).
- Drag to draw, click to select, drag to move, corner handles to resize.
- Detection list with class/severity/confidence/depth/area editing.
- Telemetry and environment forms per frame (saved on change).
- Keyboard: Left/Right navigate, Del remove, Esc deselect, Ctrl+S save.
- Filters (all / labeled / unlabeled), progress bar, one-click dataset export.
- Unsaved-changes guard on navigation and window close.

---------------------------------------------------------------- 6. IGNORE REGIONS (FALSE POSITIVES / NEGATIVE MINING)

- UI: "Ignore (false positive)" checkbox per detection; rendered as a gray
  dashed box (vs solid color for real detections).
- predictions.json stores the ignore flag with each detection.
- GET /api/export writes two YOLO label folders:
    labels/          - positive detections (class 0-9)
    labels_ignore/   - ignore regions (class 0-9 geometry, flagged)
- train_pipeline.py can merge labels_ignore/ into class 10 (background) via
  --ignore-as-class for hard-negative mining in YOLO training.
- COCO export skips ignore regions (standard detection format).
- C-DAC client payload omits the ignore flag (client only sees true positives).

  GET    /                              Annotator UI

  GET    /api/frames?filter=all|labeled|unlabeled

---------------------------------------------------------------- 9. TRAIN & DEPLOY LOOP (train_pipeline.py)

    python -m annotate.train_pipeline --annotations annotations --model best.pt --epochs 50
    python -m annotate.train_pipeline --annotations annotations --model best.pt --epochs 50 --ignore-as-class --tensorrt

1. Reads annotations/export/ (labels, labels_ignore, manifest.json).
2. Runs merge_ignore() if --ignore-as-class: remaps ignore regions to class 10.
3. Writes data.yaml (nc=10 or 11, names list, train/val paths).
4. Runs yolo detect train with Ultralytics (transfer from best.pt).
5. Exports best.pt -> ONNX (best.onnx).
6. With --tensorrt: builds best_fp16.engine (or best_int8.engine with --int8
   and --calib-set).
7. Copies retrained weights to inference/best_retrained.pt.
8. Instructions: set MODEL_PATH in .env and restart systemd services.

---------------------------------------------------------------- 12. DATASET TARGETS AND NEXT STEPS

Current tooling supports the dataset specification targets: 25,000-50,000
labeled frames across 150-200 routes, with a reserved 2,000-3,000 frame
calibration set for TensorRT INT8 (KL-divergence/entropy) - the export's
manifest.json makes calibration-set carving trivial.

Roadmap:
1. Wire GNSS/IMU capture into collection so telemetry auto-fills instead of
   manual entry.
2. Add LWIR thermal frames and populate bbox_thermal_xywh for fused detection.
3. Depth/area estimation heuristics from camera geometry to pre-fill
   estimated_depth_cm and estimated_area_sqcm before human review.

---------------------------------------------------------------- 14. COMPLETE PIPELINE (TRAIN -> DEPLOY -> INFERENCE)

    Annotate frames        Preannotate + UI review    Export labels
         |                        |                        |
         v                        v                        v
    train_pipeline.py:                         inference/
         | PyTorch train (Ultralytics YOLO)      best.pt   ->  ONNX  ->  TensorRT FP16/INT8 engine
         | ONNX export                           |             (best.onnx)   (best_fp16.engine)
         | TensorRT engine build (--tensorrt)    v
         v                              local_runner.py (Jetson live inference)
    best_retrained.pt                         |
    (deploy to Jetson)                        v
    sudo systemctl restart                  C-DAC JSON payloads
    pothole-runner/API                      (frame_id, telemetry, detections)
         |                                  |
         v                                  v
    TensorRT FP16 inference engine    validate_engine.py
         |                                  (accuracy + speed comparison
         v                                  PyTorch vs TensorRT on real frames)
    Faster inference: ~3-4x vs CPU
         |                                  |
         +----------------------------------+
         |
         v
    Jetson Orin Nano deployment
    (local_runner.py + server.py)

TensorRT is strictly an inference optimizer (no training/autograd). The correct
sequence is always: PyTorch retrain -> ONNX export -> TensorRT engine.
validate_engine.py performs the accuracy validation (IoU matching, missed
detections, false positives, confidence delta) and speed benchmark against the
PyTorch baseline before deployment.
